# Assessment measurement for an accepted change

Measure like-for-like work with the acceptance criteria fixed before the task
starts. One laboratory run is not a programme ROI forecast.

| Measure | Definition |
| --- | --- |
| Calendar time | From approved handoff to a review-ready draft PR |
| Active human minutes | Time spent clarifying, editing, reviewing and unblocking |
| Agent execution time | Session time spent planning, editing and validating |
| Review minutes | Human time from first review to accepted change |
| Retries | Repeated agent or gate runs needed for the same failure |
| Rework | Code changed after review because acceptance criteria were missed |
| Accepted change | A PR approved under the same contract, test and control gates |
| Escaped defect | A defect found after acceptance in the defined observation window |
| Control violation | Any prohibited action, secret exposure or policy-gate bypass |
| Consumption | ACUs or the tenant's current unit, recorded without converting it to ROI alone |

For the first assessment, select three Angular slices that the bank already
expects to complete. Record the planned engineers and calendar time, then run
the Devin path under the same acceptance criteria. Compare medians and inspect
the outliers. The decision is whether the operating model produces accepted
changes with less human effort or cycle time without increasing rework,
defects or control violations.
