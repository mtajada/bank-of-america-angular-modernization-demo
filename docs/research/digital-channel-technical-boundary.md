how the Angular 14-to-18 case should be modelled. It is not an inventory of Bank

## Model used in the repository

- **Angular runtime:** the synthetic Retail Online Banking browser surface and
  the Customer Servicing browser application.
- **Responsive evidence:** desktop and narrow mobile-browser viewports for the
  Angular surface.
- **Adjacent channels:** iOS and Android applications whose implementations are
  deliberately unspecified and which do not import the Angular library.
- **Cross-channel contracts:** identity-session assurance, transaction step-up,
  transfer-domain data, analytics events and financial-provider data.
- **Discovery decision:** confirm whether the real target is browser-based
  Online Banking, responsive web inside another shell, or a broader
  cross-channel contract programme before changing the write scope.

## Claims excluded from the meeting

- The Bank of America native mobile application uses Angular.
- Public job descriptions reveal the bank's production architecture.
- A responsive web test is evidence for an iOS or Android release.
- The laboratory reproduces Bank of America's identity, analytics, provider or
  mobile implementation.

The public evidence supports a more precise boundary, not a larger demo.
